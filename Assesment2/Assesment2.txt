10. Ans10 

langchain follows the linear chaining where the output of one runnable is treated as input for next runnable where langgraph shares the same memory StrOutputParser
langchain is used for small workflows like prompt + models , whereas langgraph is used for complex agents where multiple tool_calls are involved
Loops in langchain are need to be created manually , whereas in langgraph nodes can even perform cyclic and conditional branching
langchain has limited branching whereas langgraph provides routing and conditional branching

langgraph can perfoem cyclic workflows whereas langchain follows sequential chaining and execution



11. 
    state : state is the shared memory that all nodes can access and updates 
    node : nodes are the functions or execution to update state
    edges : edges decide the workflow in which it decides which node to be executed after current node
    conditional edges : it decides the next node dynamically on the basis of condition that may happened in the previous node


    execution starts at START node to first node where it will perform its execution and updates the state and then the updated state will be accessed by the next state and so on and execution ends at END node

from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class graph_schema(TypedDict):
    messages: list

def greet(state: GraphState):
    messages = state['messages']

    temp = ['Hello!']
    state['messages'] = messages.append(temp)

    return state

def farewell(state: GraphState):
    messages = state['messages']

    temp = ['Goodbye!']
    state['messages'] = messages.append(temp)

    return state

graph = StateGraph(graph_schema)

graph.add_node("greet", greet)
graph.add_node("farewell", farewell)

graph.add_edge(START, "greet")
graph.add_edge("greet", "farewell")
graph.add_edge("farewell", END)

final_graph = graph.compile()

res = final_graph.invoke(
    {"messages": []}
)

print(res)

14. Ans 14

a.  MCP (Model Context Protocol) provides a standardized way for AI applications to connect with external tools, APIs, databases, and data sources, eliminating the need for custom integrations for each service.

b.  Host -> The Host is the AI application (e.g., an IDE, chatbot, or desktop AI app) that wants to access external capabilities through MCP.
    Client -> The Client acts as an intermediary between the Host and MCP Servers, handling communication and protocol management.
    Server -> The Server provides external functionality, data, or prompts that can be used by the AI application.

c.  Tools -> Tools are executable functions or actions that the AI can invoke, such as sending emails, querying databases, or calling APIs.
    Resources -> Resources are data sources that the AI can read, such as files, documents, database records, or web content.
    Prompts -> Prompts are reusable prompt templates provided by the server to guide the AI in performing specific tasks.


15. Ans 15 

A tool is an executable action that the AI can invoke to perform a task; for example, a tool that sends an email through Gmail when the user asks the AI to contact someone. whereas , A resource is a source of data that the AI can read but not execute; for example, a PDF file containing company policies that the AI accesses to answer employee questions.

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("Word Count Server")

@mcp.tool()
def word_count(text: str) -> int:
    """Count the number of words in the given text."""
    return len(text.split())

mcp.run()


17. Ans 17 

Write once, use everywhere. With normal function calling, you usually have to create and maintain separate integrations for each LLM provider. MCP gives you a standard interface, so a tool built once can work across different AI applications and models without rewriting the integration.
Easier to connect external systems. Function calling only tells the model how to call a function, but MCP provides a complete way to expose tools, data sources, and reusable prompts. This makes it much simpler to plug an AI application into databases, files, APIs, and other services in a consistent way.
